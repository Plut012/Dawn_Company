Eval 05 — Server

A plain protocol console on the real server, over /ws (through Vite's proxy to npm run server on port 8080; add ?ws=ws://host:port/ws to the page address to talk to a server somewhere else). Each column is its own socket and its own seat. Every message the server sends is logged as it arrives, with the unit counts of the view it carries: own / enemy / visible hexes. Nothing here is mocked and nothing decides an outcome.

Try: Table of four, Start in the first column, then Sample move or Hold all in each column. The round resolves when every seat is ready or the server's timer fires (default 90 s). Disconnect a seat mid-match, then Reconnect: it returns to the same seat by token. Each seat's resolve and plan lines carry only that seat's units; compare the counts.

Resume

The match log is one JSON line per round in matches/<timestamp>.jsonl (first line: map, seat names, tokens, squads). To test it:

npm run server -- --timer 0                 # play a few rounds with this page, note the round and scores
kill -9 <server pid>                        # the crash
npm run server -- --timer 0 --resume matches/<file>.jsonl
# then press Reconnect in each column: the same seats come back by token

Observed (live run on port 8097 with scripted sockets, four seats, four rounds resolved, one of them by the 4 s timer with a seat missing): the server was killed with kill -9 while in round 5; restarted with --resume it printed "Resumed ... at round 5 (playing)". All four tokens were accepted, each seat got welcome with its old seat number and a plan whose view was byte-for-byte identical to the one seen before the kill (round 5, scores 0,0,0,0, same units and positions). The planning timer restarted at the first seat's return. Rounds played after the resume are appended to the same file. The unit test src/server/match.test.ts ("replaying the log gives the same state as the live match") compares the whole game state after moves.
