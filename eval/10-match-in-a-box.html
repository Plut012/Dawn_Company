Eval 10 — Match in a box

Needs npm run server (port 8080) and npm run dev. Everything recorded below was run on 2026-11-17 on the development laptop (Linux, Node 22), the browser parts in headless Chromium driven with real mouse and touch events at computed pixels. No person and no physical phone took part; where that matters it is said.

1. All seats on one screen

/dev.html opens on its own (2, 3 or 4 seats, phone- or laptop-shaped frames, "Quick start", "Clear dev seats", a Reload key per frame). The copy below is the same page at two phone-shaped seats: press Quick start, then Start in dev1, and play. Start the server fresh (and press Clear dev seats) if the frames show an old match.

Quick start only sets each frame's URL to /?slot=devN&auto=<preset id>&name=…. The client honours auto only when the slot starts with dev (src/client/dev.ts, tested in src/client/dev.test.ts). Checked in a browser against the production build as well: /?slot=guest&auto=support shows the ordinary join form and joins nothing; /?slot=dev7&auto=support&name=Devvy is seated, readied, with the Weapons section.

2. The bot run

scripts/bots.ts starts the real server (src/server/main.ts, no timer) on a spare port with a temporary log directory, seats 2–4 WebSocket clients, and plays whole matches by protocol alone. Each bot gives each living unit a random order (or none) from orderOptions on its own view. At about six tables in ten the bots are also "keen": they prefer to fire at a hex where they see an enemy and to end moves nearer the middle objective, so that squads meet and are wiped. Without that, random walkers almost never eliminate anyone and the elimination paths would go untested. About one order turn in 25, a bot drops its socket and rejoins by token first.

What is checked, every round, for every bot:

  • the view holds no enemy unit, and lists no hex, that the bot's own units could not see (sight range, line, cover and stealth range worked out again from the view alone); and no visible hex is missing;
  • across the seats: every enemy the sight rule gives a seat is in its view, identical to its owner's copy; scores, round and end agree between seats;
  • no rejected and no error for orders taken from orderOptions;
  • events name only units the bot knows (own, in the last view, or spotted since), and followed through (moves, hits, recoveries, spotted, lost) they arrive at exactly the next view's units, positions and statuses;
  • scores never go down; the round number goes up by one; the match is over by round 12; nothing waits more than 10 s;
  • after a rejoin the view is the same as before it; the server writes nothing to stderr;
  • at the end, the server's .jsonl log replayed through createMatch and resolve ends the match with the same scores and winners, and holds the squads the bots sent.

The checks were themselves checked by breaking the rules on purpose and putting them back: with the stealth rule removed from visibleEnemies the run fails with "view holds enemy 0-2 at 3,3 (ready) that no own unit can see" and exit code 1; with hit events sent to everyone it fails with "event … names unit 1-1, which this seat does not know". A failing match prints its own re-run line, e.g. npm run bots -- --seed 2 --players 3 --matches 1.

The bots are not in the client: scripts/ is imported by nothing under src/, and the built bundle was searched for the script's strings and has none.

3. Bugs found and fixed

None. 7,800 bot matches and the hand checks below found no fault in the code of tasks 01–09, so no earlier file was changed apart from one line in src/client/main.ts that calls the dev-slot shortcut, and tsconfig.json, which now also type-checks scripts/. Things that are not faults but were noticed are in section 6 and under "Open items" in the plan.

"By hand" here means: through dev.html (or the client alone) in headless Chromium, every action a real click or tap at a pixel (unit card, order chit, hex on the map, lever, keys), the DOM read only to find where to press and what is shown. The orders themselves were chosen by a small script (fire at a visible enemy, else move toward an objective, else ambush), not by a person.

What was noticed on the way is under "Open items" in docs/tasks/00-plan.md: focus fire kills in one round, a squad can win after being wiped out, the planning timer runs during playback, squads jam in their own spawn zone, the small builder keys and chit words on a phone.
  • Not a fault, but visible: every page that draws the board logs one three.js warning ("PCFSoftShadowMap has been removed. Using PCFShadowMap instead."). The look is what three already falls back to. Left alone here; one line in src/client/render/index.ts would silence it.
  • Not a fault, by design of the tools: a browser tab in the background does not draw the board (no animation frames), so two seats in two tabs of one window cannot both be watched; that is what dev.html is for.
  • Port 5173 was taken by another program on this machine, so npm run dev itself stopped with "port in use" (it is strictPort); the pages were checked through npm run dev -- --port 5191, which is the same server on another port, including this page.
