Eval 17 — Modes and a map per player count

A match is played in a mode, picked by the host in the lobby: Supply Line (default) or Last Stand. Here a mode only restricts the squad builder; the rules switches come with 18 and 20. The map follows from the number of players (mapFor). Part 1 needs a game server and Vite; Part 2 needs only Vite.

Not checked by the implementer: headless Firefox in the implementer's sandbox cannot render the WebGL board, so the mode name in the play screen's header and the results panel's label was not seen on screen; that part is covered only by the typecheck and by view.mode in the tests. The lobby frames are plain DOM (no board) and the walk-through below was run against them in a headless Chromium (12 of 12 steps passed).

1. Two real clients in the lobby

Start a game server on a spare port and point a Vite from the repo root at it. These commands leave a server on 8080 and the usual Vite on 5173 alone:

npx tsx src/server/main.ts --port 8097 --matches /tmp/ds17-matches
DS_SERVER_PORT=8097 npx vite --port 5197 --strictPort
# then open  http://localhost:5197/eval/17-modes-and-map-per-player-count.html

The two frames are the real client (/?slot=dev17a, dev17b). A is the host (seat 0), B the second seat. Both start with the Line section, which has a mortar. You can click in the frames yourself; the Run the walk-through button clicks the same keys through the frames' own DOM (same origin) and reads back what each lobby shows, so the lines below it come from the real screens, not from the page.

Press Seat both. If a frame shows a match, a server from an earlier run is still up: restart it, then press Forget seats.

    2. mapFor, called live

    Each row is a call made when this page loaded, to the real src/content. The preferred map is the one whose spawns.length equals the number of players; otherwise the first map in MAPS with a seatSpawns layout for that many. Today crossroads has four zones, so for 2 and 3 players it is the fallback; tasks 22 and 23 add maps made for 2 and 3.

    3. Presets against modes

    validateSquad(units, mode) for each preset and mode, live. The lobby offers only the sections a mode allows; Last Stand needs at least one, and the Scout section has no mortar.

    What does not work, or was not looked at

    • The mode's name in the play screen header and the results panel label is wired (MODES[view.mode].name) but has not been seen on screen: no WebGL in the implementer's sandbox, so no match was shown in a frame.
    • A mode message from a non-host seat is refused and an unknown mode is refused; both are in src/server/match.test.ts, not in this page (the page's frames cannot send a message the client UI never sends).
    • Phone-size layout of the new Mode panel was not tried; it uses the lobby's existing stack and wraps.
    • The mode changes nothing in resolution yet: a Last Stand match plays by Supply Line rules (flags still score, downed units stay down) until 18 and 20. The seeded digests moved only because the state has a new field (see the note in src/rules/digest.test.ts).
